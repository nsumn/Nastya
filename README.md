# Telegram-бот приёма оплаты (Platega / Карта РФ / Telegram Stars)

Бот для продажи доступа к тарифам с тремя способами оплаты:

| Способ | Как работает |
|--------|--------------|
| 📲 **СБП** | Через платёжную систему **Platega.io**. Бот создаёт счёт, пользователь оплачивает, **бот автоматически проверяет оплату** (вебхук + резервный опрос статуса) и сам выдаёт ссылку на канал. |
| 💳 **Карта РФ** | Ручной режим: бот показывает реквизиты, пользователь оплачивает и присылает чек. **Чек прилетает администратору в личку**, администратор проверяет вручную и **переписывается с покупателем прямо в чате бота**, затем присылает ссылку на канал. |
| ⭐ **Telegram Stars** | Просто ссылка на другой канал. |

## Сценарий

1. `/start` → приветствие + кнопка тарифа (**VIP ОГЭ 2026**).
2. Кнопка тарифа → карточка тарифа (название, цена `1590.0 RUB`, срок «навсегда», описание) + кнопка **Оплатить**.
3. **Оплатить** → выбор способа: СБП / Карта РФ / Telegram Stars.
4. Дальше — по таблице выше.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # заполни своими значениями
python -m bot.main
```

## Настройка (`.env`)

Главные параметры (полный список с комментариями — в `.env.example`):

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
- `ADMIN_CHAT_ID` — твой `chat_id` (узнать у [@userinfobot](https://t.me/userinfobot)). Сюда приходят чеки и здесь ты переписываешься с покупателями.
- `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` — данные из ЛК Platega.
- `PLATEGA_SBP_METHOD` — метод оплаты в Platega (по умолчанию `2` = СБП).
- `PUBLIC_BASE_URL` — публичный адрес бота для вебхука Platega.
- `CHANNEL_LINK` — ссылка на канал, которую бот выдаёт после оплаты по СБП.
- `STARS_LINK` — ссылка для оплаты Telegram Stars.
- `CARD_DETAILS` — реквизиты для оплаты картой РФ.
- `REVIEWS_LINK`, `ADMIN_LINK` — ссылки для кнопок «Отзывы» и «Администрация» в приветствии (необязательно).

### Подключение вебхука Platega (для авто-проверки СБП)

Бот поднимает HTTP-сервер на `PORT` (по умолчанию `8080`) с эндпоинтом:

```
POST <PUBLIC_BASE_URL>/platega/callback
```

Укажи этот URL в личном кабинете Platega как адрес callback. Бот проверяет
заголовки `X-MerchantId` / `X-Secret` и отвечает `200 OK`.

> Если вебхук не настроен или не дошёл — оплата всё равно подтвердится:
> после создания счёта бот **сам опрашивает статус** транзакции (polling),
> а у пользователя есть кнопка «🔄 Проверить оплату».

## Как переписываться с покупателем (Карта РФ)

1. Пользователь жмёт «✅ Оплатить и отправить чек» и присылает чек.
2. Тебе в ЛС приходит уведомление и сам чек.
3. **Ответь reply** на сообщение пользователя — твой ответ придёт ему в чат бота
   (так можно писать «не вижу чека», задавать вопросы и т. д.).
4. Когда оплата подтверждена — просто **отправь ему reply со ссылкой на канал**.

## Автопостинг из другого канала в свой (без «Переслано»)

Посты чужого канала появляются у тебя **копией**, а не пересылкой: у
читателей не видно ни «Переслано из …», ни ссылки на источник.

Способов два — они отличаются только тем, кто читает чужой канал.

### Вариант 1 (для ЧУЖОГО канала) — от личного аккаунта

Бота нельзя сделать администратором чужого канала, а без админки Telegram
не отдаёт боту посты. Поэтому чужой канал читает твой личный аккаунт
(достаточно быть на него подписанным), а публикует в твой канал скрипт
`tools/userbot_mirror.py` (Telethon) — отдельным процессом от бота.

```bash
pip install -r tools/requirements.txt
```

> **Если my.telegram.org отвечает `ERROR` или «too many attempts».** Сайт
> часто ломается в мобильных браузерах и блокирует повторные попытки по
> адресу в сети. У сервера адрес другой — получи ключи прямо с него:
>
> ```bash
> python tools/get_api_keys.py
> ```
>
> Спросит номер и код из Telegram, создаст приложение, покажет `api_id` и
> `api_hash` и предложит сразу записать их в `.env`.

В `.env` (тот же файл, что у бота):

```
TG_API_ID=1234567                 # my.telegram.org → API development tools
TG_API_HASH=abcdef...
MIRROR_SOURCES=-1001111111111     # чужой канал (можно @username или ссылку t.me)
MIRROR_TARGETS=-1002222222222     # твой канал
# либо, если каналов несколько и каждый идёт в свой:
# MIRROR_ROUTES=-1001111111111>-1002222222222,-1003333333333>-1004444444444
MIRROR_DELAY=180                  # публиковать через 3 минуты, а не секунда в секунду
MIRROR_REMOVE_LINKS=1             # вырезать чужие @юзернеймы и t.me-ссылки
MIRROR_FOOTER=Подписывайся: @my_channel
MIRROR_REPLACE=старый канал=>наш канал
MIRROR_SKIP=реклама, #ad
```

Дальше:

```bash
python tools/userbot_mirror.py --list      # ID каналов (первый запуск спросит
                                           # телефон и код из Telegram)
python tools/userbot_mirror.py --dry-run   # показать, как посты будут выглядеть,
                                           # ничего не публикуя
python tools/userbot_mirror.py --last 10   # разом скопировать 10 последних постов
python tools/userbot_mirror.py             # рабочий режим: слушать канал
```

Сессия сохраняется в `mirror.session`, память о скопированных постах — в
`mirror_state.json` (после перезапуска ничего не задвоится). Автозапуск —
юнит `deploy/mirror-userbot.service`.

Если в источнике включена защита контента («запрет сохранения»), скрипт
скачает медиа и зальёт заново — пост всё равно опубликуется.

### Вариант 2 (для СВОЕГО канала) — от бота

Если в канал-источник можно добавить бота администратором (например, это
твой второй канал), зеркало умеет и сам бот, отдельный процесс не нужен:

1. Добавь бота админом в источник (достаточно права «Просмотр») и в свой
   канал (право «Публиковать сообщения»).
2. Узнай ID каналов: перешли боту в личку любой пост из канала — он ответит
   `ID: -100…`.
3. В `.env` поставь `MIRROR_ENABLED=1` и заполни `MIRROR_SOURCES` /
   `MIRROR_TARGETS` (остальные `MIRROR_*` — те же, что выше), перезапусти бота.
4. Команда `/mirror` у администратора показывает статус, `/mirror on` и
   `/mirror off` — включают и выключают на лету.

### Что умеют оба варианта

- альбомы (несколько фото одним постом) публикуются альбомом;
- текст чистится: вырезаются t.me-ссылки и @юзернеймы источника, работают
  твои замены слов и своя подпись в конце;
- посты со стоп-словами (`MIRROR_SKIP`) пропускаются;
- задержка публикации (`MIRROR_DELAY`);
- один и тот же пост не публикуется дважды даже после перезапуска;
- у бота дополнительно: правка поста в источнике подтягивается в копию
  (`MIRROR_SYNC_EDITS=1`).

Чего нельзя: узнать, что пост **удалили** в источнике — копия останется,
удалять руками.

Про аккуратность: автоматизация личного аккаунта — это не Bot API, за
массовое зеркалирование аккаунт может получить ограничения. Ставь
`MIRROR_DELAY` и не вешай на один аккаунт десятки каналов. И отдельно:
копирование чужого контента без разрешения автора — вопрос к
правообладателю, техника тут ни при чём.

## Добавить новый тариф

Открой `bot/config.py`, скопируй блок `Tariff(...)` в функции `load_config`,
поменяй `id`, `button`, `title`, `price`, `description` и добавь в словарь
`tariffs`. Кнопки в приветствии построятся автоматически.

## Структура

```
bot/
  config.py      — конфигурация и тарифы
  texts.py       — тексты сообщений
  keyboards.py   — инлайн-клавиатуры
  database.py    — SQLite: заказы и карта переписки
  platega.py     — клиент Platega.io API
  services.py    — выдача доступа и опрос статуса
  webhook.py     — приём вебхуков Platega (aiohttp)
  handlers/
    start.py     — /start и навигация по тарифам
    payment.py   — способы оплаты (СБП / карта / stars)
    relay.py     — двусторонний чат покупатель ⇄ администратор
    mirror.py    — автопостинг из чужого канала в свой (без «Переслано»)
  main.py        — точка входа
tools/
  userbot_mirror.py — зеркало чужого канала от личного аккаунта (Telethon)
  get_api_keys.py   — получение api_id/api_hash с сервера, без браузера
```

## Технологии

- [aiogram 3](https://docs.aiogram.dev/) — Telegram Bot API
- aiohttp — приём вебхуков
- aiosqlite — хранилище заказов и переписки
