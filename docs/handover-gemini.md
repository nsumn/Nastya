# Передача проекта: боты Roblox + админ-панель

Вставь этот файл целиком в новый чат с Gemini. Дальше в этом же чате
показывай Gemini код файлов (командой `cat путь/к/файлу` в Термиусе) и
проси менять — он должен присылать готовый файл целиком, а не «патч»,
чтобы было легко вставить его обратно через `nano`.

---

## Что это за проект

Репозиторий на GitHub: `nsumn/Nastya`, ветка
**`claude/telegram-roblox-account-checker-633oas`**.
Три Telegram-бота на Python (aiogram 3), один процесс на каждый, плюс
общий SQLite и общий JSON-файл настроек:

1. **RB DAYS** — мини-приложение: человек вводит ник в Roblox, видит
   дату регистрации аккаунта и сколько дней ему лет. Доступ — только
   после подписки на список каналов-спонсоров.
2. **Карта / обby-приглашение** («карта», `BOT_MODE=map`) — похожий
   бот: находит аккаунт по нику, после подписки на спонсоров ставит
   заявку на приглашение в Roblox-игру (обby), с таймером 24 часа.
   Один Telegram-пользователь может получить приглашение только на
   один Roblox-аккаунт (это специально, для контроля).
3. **Админ-панель** (`@adddminnnoppppbot`) — отдельный бот, через
   который разом меняется список спонсорских ссылок во всех ботах
   выше (они читают один и тот же файл настроек).

## Сервер

VPS: `138.124.78.145`. На нём уже работает **третий, отдельный** бот
продажи тарифов ОГЭ — служба `nastya-bot`, папка `/opt/nastya-bot`,
порт **8080**. Его нельзя трогать, останавливать, менять код или `.env`.

Этот проект стоит отдельно, в `/opt/rbdays`, порт **8081**, свои
systemd-службы:

- `rbdays-bot` — бот RB DAYS (`bot/main.py`, `BOT_MODE=roblox`)
- `rbmap-bot` — бот «карта» (тот же `bot/main.py`, но `BOT_MODE=map`,
  свой `.env` и своя папка/порт — уточни у пользователя, как именно
  сейчас разнесены .env-файлы для второго бота)
- `rbdays-panel` — панель (`panel/main.py`)

Общие команды в Термиусе:

```bash
cd /opt/rbdays
git pull                                  # забрать новый код
systemctl restart rbdays-bot rbmap-bot rbdays-panel
systemctl status rbdays-bot               # проверить, что жив
journalctl -u rbdays-bot -n 50 --no-pager # логи/ошибки
nano bot/miniapp/index.html               # править файл руками
cat bot/roblox.py                         # посмотреть файл целиком
```

nginx проксирует домен(ы) на `127.0.0.1:8081`, https через certbot.
Домен управляется через DuckDNS (если что-то с сертификатом — сначала
проверить, что DuckDNS указывает на актуальный IP сервера).

## Структура кода

- `bot/main.py` — точка входа, поднимает бота и веб-сервер в одном
  процессе. `BOT_MODE` (`roblox` / `map` / `payments`) выбирает, какие
  роутеры и какая страница мини-аппа подключаются.
- `bot/config.py` — все настройки читаются из `.env`.
- `bot/roblox.py` — клиент публичного API Roblox (без ключей): ник →
  id → дата регистрации/аватар/друзья. Есть кэш на 5 минут. Поиск
  сначала по точному логину, если не найден — по отображаемому имени
  (`_search_id`, эндпоинт `/v1/users/search`).
- `bot/op.py` + `bot/op_store.py` — обязательная подписка (ОП):
  список каналов-спонсоров, проверочная ссылка/канал, тексты экранов.
  Состояние — общий JSON-файл (путь в `OP_STATE_FILE`), с
  файловой блокировкой, чтобы боты не портили друг другу запись.
  Тексты (`welcome_text`, `button_text`, `reward_text` и т.д.) у
  каждого бота свои — через `op.set_scope(bot_mode)`.
- `bot/handlers/op_admin.py` — админ (Telegram ID `413124905`) шлёт
  боту обычным сообщением дневной список ссылок — бот сам разбирает
  его и обновляет спонсоров; следующим сообщением — новая проверочная
  ссылка; пересланный пост из канала — задаёт проверочный канал.
  Команды: `/op`, `/stats`, `/invites`, `/sent`, `/maplink`, `/bonus`,
  `/welcome`, `/button`, `/reward`.
- `bot/handlers/roblox.py` — обработка ника, показ карточки профиля,
  учёт статистики (`my_chat_member` — блок/разблок бота,
  `chat_member` — вступление/выход из проверочного канала).
- `bot/webapp.py` — веб-сервер мини-аппов: страницы `/app` (RB DAYS) и
  `/map` (карта/обby), API `/api/roblox/user`, `/api/op/status`,
  `/api/invite`. Все запросы подписаны Telegram `initData`, сервер
  проверяет HMAC-подпись — **важно**: если открыть мини-апп кнопкой
  клавиатуры (`ReplyKeyboardMarkup`), Telegram не передаёт `initData`
  вообще (так у Telegram устроено), поэтому запуск мини-аппа идёт
  только через инлайн-кнопку и кнопку-меню у поля ввода.
- `bot/database.py` — SQLite: таблицы `users`, `events`, `invites`,
  плюс старые `orders`/`payments`/`relay`/`settings` от бота ОГЭ.
- `bot/miniapp/index.html` — страница RB DAYS (белый Roblox-стиль).
- `bot/miniapp/map.html` — страница «карта» (чёрно-белый OBBY INVITE),
  экраны: интро → поиск → результат → подписка на спонсоров →
  ожидание (таймер 24ч) → готово.
- `panel/main.py` — бот-панель, читает/пишет тот же `op_store`.

## Текущее состояние

- Оба мини-аппа показывают **только отображаемое имя** (display name)
  из Roblox, логин (username) нигде не выводится — это сознательное
  решение по приватности, не баг.
- Дни/возраст аккаунта считаются от реальной даты регистрации через
  Roblox API — это не константа в коде, менять «на глаз» нельзя,
  иначе для всех пользователей приложения будут показываться неверные
  данные.
- Бот RB DAYS должен быть администратором проверочного канала
  («Те самые новости»), иначе проверка подписки не работает.

## Известные грабли

- `.env` не должен начинаться с пробелов перед именем переменной —
  однажды `BOT_TOKEN=` со ведущим пробелом ломал `sed`-замену токена
  и бот падал с `Unauthorized`.
- Если бот не открывается («Открой через Telegram» / 401) — почти
  всегда причина в способе запуска мини-аппа (см. про `initData`
  выше), не в самом коде страницы.
- certbot ругается на «Connection refused» / «No such authorization»
  — обычно DuckDNS указывает не на тот IP, нужно обновить A-запись.

## Чего делать не нужно

- Не трогать `/opt/nastya-bot` и порт 8080.
- Не коммитить `.env`, `*.db`, `op_state.json` (они в `.gitignore`).
