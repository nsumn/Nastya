# JOWS — Telegram mini app «платформа заданий»

Мини-приложение внутри Telegram: лента ежедневных заданий, выполнение задания
с шаблонами и оценкой, баланс, рейтинг участников и вывод средств.
Бот вокруг приложения делает проверку подписки на каналы спонсоров и содержит
админку: задания, модерация ответов, спонсоры, выплаты.

```
miniapp/
├── app/                  бот + HTTP API
│   ├── main.py           точка входа: бот и веб-сервер в одном процессе
│   ├── config.py         конфиг из .env
│   ├── database.py       SQLite (users, tasks, submissions, withdrawals)
│   ├── api.py            REST API мини-аппа + раздача статики
│   ├── webapp_auth.py    проверка подписи Telegram initData
│   ├── op_store.py       общий JSON-файл состояния подписки (на все боты)
│   ├── op.py             списки каналов, разбор сообщения со ссылками
│   ├── services.py       гейт подписки, уведомления
│   ├── seed.py           демо-задания и витринный рейтинг
│   └── handlers/         start.py (участники), admin.py (задания, выплаты),
│                         op_admin.py (подписка и списки ссылок)
├── panel/main.py         отдельный бот-панель: меняет списки во всех ботах
└── web/                  сам мини-апп (без сборки: html + css + js)
```

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # заполнить BOT_TOKEN, ADMIN_CHAT_ID, PUBLIC_BASE_URL
python -m app.main
```

Telegram открывает мини-апп только по HTTPS. Локально удобно так:

```bash
cloudflared tunnel --url http://localhost:8080
# полученный https-адрес → в PUBLIC_BASE_URL, перезапустить бота
```

Мини-апп живёт по адресу `PUBLIC_BASE_URL/app/`. Бот сам ставит этот адрес
на кнопку меню рядом со скрепкой и на кнопку под `/start`.

### Разработка без Telegram

`WEBAPP_DEV=1` в `.env` — тогда API принимает запросы без подписи initData
и подставляет демо-пользователя. Открывайте `http://localhost:8080/app/`
прямо в браузере. **На проде обязательно `WEBAPP_DEV=0`.**

## Как это работает

**Обязательная подписка — два независимых списка.** Как в предыдущих
ботах: список каналов хранится в общем JSON-файле (`OP_STATE_FILE`),
разделов два:

- `entry` — проверка при входе в приложение: пока подписки нет, мини-апп
  показывает экран-гейт и не даёт сдавать задания;
- `payout` — проверка перед созданием заявки на вывод: пользователь жмёт
  «Продолжить», сервер отвечает `409` со списком каналов, приложение
  показывает экран «Подтвердите подписку» с нумерованным списком и кнопкой
  «Проверить подписку». Заявка создаётся только после подтверждения.

Гейт работает только там, где список действительно заведён: настроил
вывод — вход остаётся свободным, и наоборот.

Пользователю показывается **весь** список, а подписка проверяется по одному
**проверочному каналу**, в котором бот администратор: чужие каналы Telegram
проверять не даёт. Проверочная ссылка встаёт на место строки «Твоя
проверочная ссылка», а если такой строки в списке нет — добавляется в конец.
Если проверочный канал не задан или Telegram не отвечает, гейт пропускает
всех: лучше пустить, чем запереть всех из-за настройки.

**Задания.** Задание с пустым полем `day` — ежедневное: попадает в ленту
каждый день, и каждый день его можно сдать заново. Задание с датой
показывается только в этот день. Одно задание = один ответ в день
(уникальный индекс `user_id + task_id + day`).

**Начисление.** При `AUTOAPPROVE=1` деньги падают на баланс сразу после
отправки. При `AUTOAPPROVE=0` ответ уходит в очередь модерации: админ жмёт
«Принять» — тогда начисляем, «Отклонить» — задание снова доступно.

**Вывод.** Три способа: СБП (телефон), карта РФ (16 цифр), иностранная карта
(13–19 цифр). Реквизиты проверяются и на клиенте, и на сервере. Порядок:
выбор способа → «Проверить данные» → экран «Проверьте реквизиты» →
«Продолжить» → гейт подписки (если настроен) → заявка.

**Демо для показа заказчику.** У администратора заявка на вывод сразу
помечается доставленной, и приложение показывает экран «Платёж доставлен» —
чтобы можно было показать, как выглядит успешная выплата, не трогая
настоящие деньги. На обычных участников это не влияет: у них заявка уходит
в обработку. Выключается `DEMO_PAYOUT_FOR_ADMIN=0`. Имя и аватар администратора
в приложении задаются через `DEMO_ADMIN_NAME` и `DEMO_ADMIN_AVATAR`
(эмодзи или ссылка на картинку) — чтобы на показе профиль выглядел так,
как нужно заказчику. Обычных участников это не касается. Команда `/demo`
наполняет профиль администратора примерами заявок во всех трёх статусах,
`/demo clear` их убирает.

У каждой заявки есть номер вида `RO-860865`. В профиле — «История вывода»
со статусами: «В обработке» (`pending`), «Выплачено» (`paid`), «Ошибка»
(`rejected`); по нажатию открываются детали заявки. Заявка уходит админу
в личку с кнопками «Выплачено» / «Отклонить»; при отклонении сумма
возвращается на баланс. Минимум задаётся `MIN_WITHDRAW`.

## Безопасность

Все запросы к API авторизуются по `initData` — строке, которую Telegram
подписывает HMAC-ом на секрете из токена бота (`app/webapp_auth.py`).
Никакому `user_id` из тела запроса сервер не верит, поэтому баланс нельзя
накрутить подделанным запросом. Проверяется и возраст подписи (сутки).

## Админка

Настраивать руками ничего не нужно — админ просто пишет боту:

1. **Прислал сообщение со списком ссылок** (как приходит от координатора ОП,
   можно переслать как есть) → список сразу обновился. Порядок сохраняется,
   служебные абзацы отбрасываются, пометки в скобках вида «(добавь группу)»
   уходят в подпись канала.
2. **Следующим сообщением прислал проверочную ссылку** → она встала на место
   строки «Твоя проверочная ссылка».
3. **Переслал пост из проверочного канала** → бот запомнил, по какому каналу
   проверять подписку. То же происходит, когда бота делают админом канала.

`/op` — состояние подписки: сколько ссылок в каждом разделе, проверочный
канал, кнопки «вкл/выкл проверку», «следующий список → вход/вывод»,
предпросмотр и очистка.

Нижние кнопки у администратора (появляются после `/start`):

| Кнопка | Что делает |
|--------|------------|
| 📢 Подписка | то же, что `/op` |
| 📋 Задания | список, добавление по шагам, включение/выключение, удаление |
| 💸 Выводы | очередь заявок, отметка «выплачено» / «отклонить» |
| 🧾 Модерация | очередь ответов, если `AUTOAPPROVE=0` |
| 📊 Статистика | за период с момента смены ссылок и за всё время |
| 👀 Приложение | открыть мини-апп глазами участника |
| ♻️ Начать заново | сбросить свои задания, заявки и баланс — чтобы показать демо ещё раз |

Команды: `/op`, `/tasks`, `/wd`, `/subs`, `/stats`, `/welcome <текст>`,
`/button <текст>`, `/paid <id>`, `/reject <id>`, `/give <user_id> <сумма>`,
`/demo` (примеры заявок для показа заказчику), `/reset` (сбросить свой
аккаунт и показать путь заново).
Команды с текстом, вызванные без аргумента, показывают текущее значение
и подсказывают, как его сменить.

### Отдельный бот-панель

`panel/main.py` — второй бот со своим токеном (`PANEL_BOT_TOKEN`). Он пишет
в тот же `OP_STATE_FILE`, поэтому списки меняются сразу во всех ботах,
которые смотрят в этот файл. Кнопки: «🚪 Ссылки: вход», «💸 Ссылки: вывод»,
«👀 Как видят люди», «🤖 Мои боты» (кто подключён и у кого хватает прав
проверять подписку), «📋 Состояние».

Запуск: `python -m panel.main`.

## API

Все ручки требуют заголовок `X-Telegram-Init-Data`.

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/bootstrap` | пользователь, гейт, статистика, лента заданий |
| POST | `/api/subscription/check` | перепроверить подписку (`scope`: `entry` / `payout`) |
| POST | `/api/task/submit` | сдать задание |
| GET | `/api/top` | рейтинг |
| GET | `/api/profile` | баланс, статистика, история операций |
| POST | `/api/withdraw/preview` | проверить реквизиты перед подтверждением |
| POST | `/api/withdraw` | создать заявку; `409` + список каналов, если нет подписки |
