# VOXY — Telegram mini app «платформа заданий»

Мини-приложение внутри Telegram: лента ежедневных заданий, выполнение задания
с шаблонами и оценкой, баланс, рейтинг участников и вывод средств.
Бот вокруг приложения делает проверку подписки на каналы спонсоров и содержит
админку: задания, модерация ответов, спонсоры, выплаты.

```
miniapp/
├── app/                  бот + HTTP API
│   ├── main.py           точка входа: бот и веб-сервер в одном процессе
│   ├── config.py         конфиг из .env
│   ├── database.py       SQLite (users, tasks, submissions, withdrawals, sponsors)
│   ├── api.py            REST API мини-аппа + раздача статики
│   ├── webapp_auth.py    проверка подписи Telegram initData
│   ├── services.py       проверка подписки, уведомления
│   ├── seed.py           демо-задания и витринный рейтинг
│   └── handlers/         start.py (гейт подписки), admin.py (админка)
└── web/                  сам мини-апп (без сборки: html + css + js)
```

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # заполнить BOT_TOKEN, ADMIN_CHAT_ID, PUBLIC_BASE_URL
python -m app.main
```

Telegram открывает мини-апп только по HTTPS. Локально удобно так:

```bash
cloudflared tunnel --url http://localhost:8080
# полученный https-адрес → в PUBLIC_BASE_URL, перезапустить бота
```

Мини-апп живёт по адресу `PUBLIC_BASE_URL/app/`. Бот сам ставит этот адрес
на кнопку меню рядом со скрепкой и на кнопку под `/start`.

### Разработка без Telegram

`WEBAPP_DEV=1` в `.env` — тогда API принимает запросы без подписи initData
и подставляет демо-пользователя. Открывайте `http://localhost:8080/app/`
прямо в браузере. **На проде обязательно `WEBAPP_DEV=0`.**

## Как это работает

**Проверка подписки.** Каналы спонсоров хранятся в таблице `sponsors`
(добавляются в админке). При `/start` и при каждом запросе к API бот проверяет
`getChatMember` по каждому каналу. Пока подписки нет — мини-апп показывает
экран-гейт и не даёт сдавать задания. Если бот не админ канала и проверить
не может, подписка считается выполненной (иначе пользователи заперты навсегда).

**Задания.** Задание с пустым полем `day` — ежедневное: попадает в ленту
каждый день, и каждый день его можно сдать заново. Задание с датой
показывается только в этот день. Одно задание = один ответ в день
(уникальный индекс `user_id + task_id + day`).

**Начисление.** При `AUTOAPPROVE=1` деньги падают на баланс сразу после
отправки. При `AUTOAPPROVE=0` ответ уходит в очередь модерации: админ жмёт
«Принять» — тогда начисляем, «Отклонить» — задание снова доступно.

**Вывод.** Три способа: СБП (телефон), карта РФ (16 цифр), иностранная карта
(13–19 цифр). Реквизиты проверяются и на клиенте, и на сервере. Заявка
уходит админу в личку с кнопками «Выплачено» / «Отклонить»; при отклонении
сумма возвращается на баланс. Минимум задаётся `MIN_WITHDRAW`.

## Безопасность

Все запросы к API авторизуются по `initData` — строке, которую Telegram
подписывает HMAC-ом на секрете из токена бота (`app/webapp_auth.py`).
Никакому `user_id` из тела запроса сервер не верит, поэтому баланс нельзя
накрутить подделанным запросом. Проверяется и возраст подписи (сутки).

## Админка

`/admin` — панель с разделами:

| Раздел | Что делает |
|--------|------------|
| 📊 Статистика | участники, выполненные задания, суммы на балансах и выплаты |
| 📋 Задания | список, добавление по шагам, включение/выключение, удаление |
| 💸 Выводы | очередь заявок, отметка «выплачено» / «отклонить» |
| 📣 Спонсоры | каналы для проверки подписки |
| 🧾 Модерация | очередь ответов, если `AUTOAPPROVE=0` |

Команды: `/paid <id>`, `/reject <id>` — по заявке на вывод;
`/give <user_id> <сумма>` — ручное начисление.

## API

Все ручки требуют заголовок `X-Telegram-Init-Data`.

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/bootstrap` | пользователь, гейт, статистика, лента заданий |
| POST | `/api/subscription/check` | перепроверить подписку |
| POST | `/api/task/submit` | сдать задание |
| GET | `/api/top` | рейтинг |
| GET | `/api/profile` | баланс, статистика, история операций |
| POST | `/api/withdraw/preview` | проверить реквизиты перед подтверждением |
| POST | `/api/withdraw` | создать заявку на вывод |
