# План перехода конвейера на Blender (GPU)

Основание: тест на RTX 3060 (см. `TOPICS_03.md`, раздел «Тест на домашнем компьютере с видеокартой»).
Cycles на видеокарте с OptiX-шумодавом даёт **1.85 с на кадр** при 32 сэмплах, то есть 60-секундный ролик
считается примерно **за час в один процесс**. Нынешний three.js + HQ-слой на SwiftShader даёт 6–9 с на кадр.

## 1. Что остаётся без изменений
- Шаг 1 (тема и текст) и шаг 2 (озвучка): `lumean.py` → `tighten.py` → `make_words.py` → `words.json`.
- Формат кадра 1080×1920, 30 fps, 60–66 с, темп 3.5–4 слова в секунду.
- Шаг 6 (сдача): длительность, 12 кадров из готового mp4, описание и 5 хештегов.

## 2. Что меняется
`engine/` (three.js) остаётся для быстрых набросков и старых роликов, новые сцены делаются в `blender/`.

```
youbuiltit_de/blender/
  scene_lib.py       общая часть: материалы (pbr_mat, flat), примитивы (box, cyl, tree, rock, human),
                     камера, небо, солнце, настройки рендера, жёлтая плашка label('3 m')
  words.py           загрузка words.json и T('Wort', n) -> секунда, как в three.js-движке
  anim.py            ease/win/pop/growTo поверх ключей Blender или прямой пересчёт в update(t)
  NN_тема.py         сцена и таймлайн конкретного ролика
  render.py          рендер диапазона кадров кусками с докачкой
  assets/            -> симлинк/копия engine/assets (Poly Haven, CC0) + модели людей
```

### 2.1 Тайминги из words.json
`words.py` повторяет логику движка: `T('Wort', n)` возвращает время n-го слова, начинающегося с `Wort`.
Грабли те же: `T('Tür')` ловит «Türme», номер обязателен; неверный номер ломает тайминг молча.
Проверка стоп-кадрами остаётся обязательной.

### 2.2 Анимация: не ключи, а `update(t)`
Самый дешёвый перенос нынешнего кода — оставить тот же подход, что в `*_main.js`:
скрипт считает позиции объектов функцией от времени и вызывается заново на каждом кадре через
`bpy.app.handlers.frame_change_pre`. Тогда `KEYS` (камера) и `tw` (времена слов) переносятся почти дословно,
и не надо расставлять ключевые кадры руками.

### 2.3 Настройки рендера (проверены тестом)
```python
sc.cycles.device = 'GPU'; cp.compute_device_type = 'OPTIX'
sc.cycles.samples = 32; sc.cycles.use_adaptive_sampling = True
sc.cycles.use_denoising = True; sc.cycles.denoiser = 'OPTIX'   # НЕ OPENIMAGEDENOISE: он на CPU, +6 с на кадр
sc.cycles.use_auto_tile = False                                 # тайлы не нужны: 2 Мп на 12 ГБ, +1 с на кадр
sc.cycles.max_bounces = 4
sc.view_settings.view_transform = 'AgX'
```
Выход — PNG (или OpenEXR при компоузинге), по кадрам, потом ffmpeg.

### 2.4 Рендер кусками с докачкой
`render.py` рендерит диапазон `--start/--end`, пропуская уже готовые файлы, как `render_burg.sh`:
```bash
blender -b -P blender/render.py -- NN_тема 1 300
```
На RTX 3060 параллелить **не надо**: видеокарта уже занята одним процессом, два процесса только делят её.
Разбиение на куски нужно только чтобы можно было прервать и продолжить.

### 2.5 Склейка
Как сейчас: `ffmpeg -framerate 30 -i frame_%05d.png -i voice_fast.mp3 -c:v libx264 -crf 21 -preset slow -pix_fmt yuv420p -af apad -shortest`.

### 2.6 Субтитры
Остаются поверх видео, не в 3D: отдельный проход ffmpeg `drawtext` или PNG-оверлеи из PIL по `words.json`
(Fredoka 700 96px, белый с чёрной обводкой, y=990). Так их можно переделать без перерендера.

## 3. Картинка: куда тянуться
Ориентир — @oddtilt и @kerozni: фото-текстуры, мягкий свет, анимированные люди.
- **Свет:** HDRI Poly Haven как источник (`engine/assets`) + солнце; фон остаётся нарисованным небом —
  HDRI в вертикальном кадре выглядит серым (грабли из `CLAUDE.md`).
- **Текстуры:** уже есть камень, дерево, трава; докупать не надо, Poly Haven CC0.
- **Люди:** в тесте это белые болванки. Нужны готовые риг-модели с ходьбой —
  Mixamo (бесплатно, FBX с анимацией) или Blender Studio. Это **главный визуальный разрыв** с конкурентами.
- **Трава и деревья:** geometry nodes со scatter вместо низкополигональных шаров — на GPU это теперь по карману.

## 4. Порядок работ
1. `scene_lib.py` + `words.py` + `render.py`, и на них пересобрать **существующий** ролик 02 (burg) — есть с чем сравнить.
2. Контактный лист из 12 кадров: сравнить с `DE_02_burg.mp4`.
3. Люди из Mixamo и трава на geometry nodes.
4. Ролик 03 (тема из `TOPICS_03.md`) делается уже в Blender.

Пункты 1–2 — примерно день работы, и до них ролик 03 на новом движке начинать не стоит.

## 5. Риски
- Blender-сцена пишется медленнее, чем three.js: нет живого просмотра в браузере. Лечится рендером стоп-кадров (1.9 с каждый).
- Файл .blend в git не кладём: сцена остаётся кодом на Python, как сейчас.
- Готовые mp4 и папки с кадрами — в `.gitignore`.
